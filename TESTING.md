# Testing the VillageSQL UUID Extension

The test suite uses the MySQL Test Runner (MTR). Every expected-output file in
`mysql-test/r/` is generated by the runner — never edit one by hand.

## Prerequisites

| Requirement | Notes |
|---|---|
| VillageSQL build tree | Provides the Extension SDK, `mysqld`, and `mysql-test/` |
| `VillageSQL_BUILD_DIR` | Environment variable pointing at that build tree |
| OpenSSL headers/libraries | Used for MD5, SHA-1, and secure random bytes |
| C++17 compiler, CMake 3.18+ | |

The SDK version must match your server version. Check both:

```bash
"$VillageSQL_BUILD_DIR"/villagesql-extension-sdk-*/bin/villagesql_config --version
mysql -u root -p -e "SHOW VARIABLES LIKE 'villagesql_server_version';"
```

If they differ, the extension may fail to load with a protocol mismatch.

## Build

```bash
export VillageSQL_BUILD_DIR=/path/to/villagesql/build
cd vsql-uuid          # repo root, the directory holding CMakeLists.txt
./build.sh
```

This produces `build/vsql_uuid.veb`.

## Install

The server loads VEB packages from the directory named by its `veb_dir`
variable. Ask the server where that is rather than assuming — `build.sh` runs
`cmake --install`, which writes to the SDK's `veb_output_directory`, and on a
development build that is **not** the same path as `veb_dir`:

```bash
mysql -u root -p -e "SHOW VARIABLES LIKE 'veb_dir';"
cp build/vsql_uuid.veb /path/from/veb_dir/
mysql -u root -p -e "INSTALL EXTENSION vsql_uuid;"
```

On a database that already has `uuid` columns, upgrade in place instead — the
swap takes effect at the next restart, and dependent columns are preserved:

```bash
cp build/vsql_uuid.veb /path/from/veb_dir/
mysql -u root -p -e "ALTER EXTENSION vsql_uuid VERSION '0.0.6' AT RESTART;"
```

For a scratch test database with no `uuid` columns, replacing the build
outright is quicker. Clear the expanded cache too, and note `UNINSTALL` is
refused while any column still uses the type:

```bash
mysql -u root -p -e "UNINSTALL EXTENSION vsql_uuid;"
rm -rf /path/from/veb_dir/_expanded/vsql_uuid
cp build/vsql_uuid.veb /path/from/veb_dir/
mysql -u root -p -e "INSTALL EXTENSION vsql_uuid;"
```

## Run the suite

MTR must be invoked from the build tree's `mysql-test/` directory, and
`--suite` must be an absolute path:

```bash
cd "$VillageSQL_BUILD_DIR"/mysql-test
perl mysql-test-run.pl --suite=/absolute/path/to/vsql-uuid/mysql-test
```

Run a single test by naming it:

```bash
perl mysql-test-run.pl --suite=/absolute/path/to/vsql-uuid/mysql-test uuid_basic
```

### Testing a build without installing it

Point `VSQL_UUID_VEB` at a `.veb` file and each test copies it into `veb_dir`
before installing:

```bash
cd "$VillageSQL_BUILD_DIR"/mysql-test
VSQL_UUID_VEB=/absolute/path/to/vsql-uuid/build/vsql_uuid.veb \
  perl mysql-test-run.pl --suite=/absolute/path/to/vsql-uuid/mysql-test
```

## Regenerating expected output

After an intentional behavior change, re-record and then read the diff before
committing it. An unexpected change in a `.result` file is a regression, not a
new baseline:

```bash
cd "$VillageSQL_BUILD_DIR"/mysql-test
VSQL_UUID_VEB=/absolute/path/to/vsql-uuid/build/vsql_uuid.veb \
  perl mysql-test-run.pl --suite=/absolute/path/to/vsql-uuid/mysql-test --record
cd /path/to/vsql-uuid && git diff mysql-test/r/
```

## Test files

| File | Covers |
|---|---|
| `mysql-test/t/uuid_basic.test` | `UUID_VERSION`, `UUID_TIMESTAMP`, `UUID_EPOCH` against known values of every version, plus NULL input |
| `mysql-test/t/uuid_compare.test` | `UUID_COMPARE` ordering, equality, and NULL handling |
| `mysql-test/t/uuid_type.test` | The `uuid` type itself: column storage, round-tripping, generation functions, version and variant bits |
| `mysql-test/t/uuid_namespace.test` | `UUID_NS_DNS`/`URL`/`OID`/`X500`, `UUID_NIL`, `UUID_MAX`, and name-based generation composed from the namespace accessors |
| `mysql-test/t/uuid_validate.test` | `UUID_IS_VALID` across accepted and rejected string forms, malformed-namespace errors, NULL propagation, bulk-generation uniqueness, generated columns and CHECK constraints, `ADD COLUMN` backfill, and aggregate behavior |

## Writing tests

- Use `#` for comments. A bare `--` is a command prefix, not a comment.
- Each test installs the extension at the top and uninstalls at the bottom, so
  a run leaves no residue.
- `generated` and other reserved words cannot be used as bare column aliases.
- Expected errors are asserted with `--error`, using the symbolic name where
  MTR knows one (`ER_CHECK_CONSTRAINT_VIOLATED`, `ER_WRONG_USAGE`,
  `ER_TRUNCATED_WRONG_VALUE_FOR_FIELD`) and the numeric code otherwise —
  `3200` is what a failing VillageSQL defined function raises.
- Never assert on a generated UUID's value; assert on its properties
  (version, ordering, distinctness).
